# 09 · 风格工作室：用库里的、改成自己的、从空白做

流程结构参考 Lemo-Opuscar 2026-10-22 更新（「把风格改成你自己的」），按本 skill 的知识片场景改写。原则同它的结语：**风格只是载体，内容才是最重要的**——先有选题和事实清单，再挑风格。

## 入口（确认 1 时一起问，用 AskUserQuestion）

1. **用库里的风格做一期**（默认）——列 `styles/INDEX.md`，按选题推荐一套排第一，附风格图。
2. **用我的风格做一期**——只在 `~/vibe-knowledge-styles/` 里已有风格时出现，排最前。
3. **改一套库里的风格，存成我的**。
4. **从空白做一套新风格**——用户用自己的话描述，或给一张图 / 一支片；从库里挑最接近的一套当「技法底子」，说明为什么选它，用户点头或换一个。

用户也可以一句话直说：「把古风改成我的品牌色」「从空白做一个黑板粉笔风，暖一点、慢一点」。

## 一题一问定方案（改风格 / 新风格时）

- **一次只问一个问题**，每题 2–4 个选项，**推荐项排第一并写理由**；最后一个选项永远是「自由对话」。
- 用户说「你定」：剩下的题按推荐填好，列一张表给他看。
- 选了「自由对话」：不再逐题问，改成一张清单（已定 / 未定，未定的每项附推荐），用户想先说哪项就说哪项。
- 大约 8–10 题，按这个顺序：
  1. **拿来做什么**：哪个系列、发哪个平台、画幅（16:9 / 9:16 / 3:4）、有没有品牌色 / logo / 固定角色 / 固定口播音色。
  2. **想改哪里**（改库里风格时）：先用这套风格自己的例子讲三分法——
     - **放心改**：配色（在原逻辑里换色）、字体、快慢、声音和乐器、加或换一个标志镜头；
     - **一改就变味**：材质和画法、配色逻辑本身、镜头语法——能改，但说清会丢掉什么；
     - **不能改**：风格的本质和底层画法——改了就是另一套，建议换底子。
     （每套的三分法写在 `styles/<key>/STYLE.md`。）
  3. **逐项细问**：只问要动的：材质、配色、字体、动态、镜头、声音、标志镜头，每项给 2–3 个具体方向。
  4. **跟哪个母版搭**：推荐 1–2 个（见各 STYLE.md 的「搭配」）。
  5. **起名字**：中文名、英文名。

## 汇总 → 风格图 → demo → 固化

1. **汇总表**：每一项「改前 / 改后 / 代价」，用户点头才动手。
2. **风格图**：用真实绘制代码出一张；改库里风格的，同一画面原版和新版并排（左原版右新版），用 stills.py 出图后 PIL 拼。两轮还不对，直说并建议换底子。
3. **demo 片 15–30 秒**：复用第 01 期开场旁白（`lessons/styles` 的做法：从已配好的旁白里截一句，拼成时间轴，B01…拍号），每一处改动至少出现一次、标志镜头必出现；做完自检一轮，交付时写明「每处改动在第几秒」。
4. **固化**：只有用户明确说「固化」才写入；之前所有东西只在本次项目目录里。

```
~/vibe-knowledge-styles/<名字>/
  STYLE.md       与库里同一结构（导演意图…三分法、搭配），首行写「底子：<库里哪一套>」
  changes.md     改前 / 改后 / 代价（汇总表原样）
  draw.js        绘制函数（从 demo 的 film.js 里抽出来，签名同 _samples：(s) => (t, a, z, B) => void）
  still.jpg      风格图
  demo.mp4       demo 片
```

以后直接点名：「用我的【夜古风】做一期乌江亭长」。底子风格以后有修复，提一句、问要不要同步，不自动改。

## 档位与模型

- 新建 / 大改风格：Opus（high 或 xhigh）。
- 用已固化的风格量产：Opus 或 Sonnet high 都可以（Lemo-Opuscar 作者实测 Sonnet 5.5 High 也稳；本 skill 尚未实测 Sonnet，第一次用要看样帧）。
- 每套风格都能出基础档（0 积分）和 Renoise 增强档（STYLE.md 里有前缀）。
